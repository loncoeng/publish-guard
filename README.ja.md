# publish-guard

[![test](https://github.com/lon-coeng/publish-guard/actions/workflows/test.yml/badge.svg)](https://github.com/lon-coeng/publish-guard/actions/workflows/test.yml)

*[English version](README.md)*

公開前のリポジトリから、消し忘れを見つけるためのツールです。**履歴にしか残っていないものも含めて**探します。

受託した仕事をもとに2つのリポジトリを公開したとき、匿名化が3通りの形で失敗していました。そのそれぞれが、このツールの機能になっています。

---

## 何が問題か

受託で作ったものを見せたい。そこで社名も認証情報もリソースIDも置き換えて公開します。

**ここで3つのことが起きます。そしてどれも、ファイルを見ている限り気付けません。**

**ファイルを編集しても、そこにあった値は消えません。** 過去のコミットがすべて持っていて、`git log -p` で読めますし、clone した人の手元にも渡ります。

**同じ値が複数の表記で現れます。** 日本語のシート名は URL の中でパーセントエンコードされ、ファイル名は正規表現リテラルの中でドットがエスケープされ、組織名は `ACME` / `Acme` / `acme` の3通りで書かれます。`json.dumps` が書き出した日本語は `\uXXXX` になり、目視では見つかりません。素の文字列を置換しても、これらはすべて残ります。

**`git push --force` では GitHub 側の何も消えません。** コミットは到達不能になるだけでオブジェクトは残り、SHA を直接指定すれば取得できます。そして **Actions の実行履歴が、その SHA を公開しています。**

## 何をするか

```
publish-guard scan   <repo>                    見落としそうな候補を洗い出す
publish-guard verify <repo> -c <config.toml>   決めた語が本当に消えたか確認する
```

`verify` は作業ツリーではなく**全コミットの全 blob** を走査します。語ごとに、実際に現れうる表記へ展開してから探します。コミットメッセージと著者情報も対象です。検出したら `1` を返すので、CI に置けます。

`scan` は何も判定しません。`売上高` が業務固有の指標名なのか一般的な語なのかは、プロジェクトを知る人にしか判断できないからです。機械が得意なのは、40文字の不透明な識別子や、ホームディレクトリのパスに埋まったユーザー名を見つけることのほうです。**丁寧に読んでも見落とすのは、むしろそちらだと思います。**

## 導入

Python 3.11 以降。依存はありません。

```sh
git clone https://github.com/lon-coeng/publish-guard.git
cd publish-guard
python -m publish_guard.cli --help
```

## 使い方

**1. 候補を洗い出す**

```sh
python -m publish_guard.cli scan /path/to/repo
```

```
[opaque-id] 20文字以上のランダムな識別子
  1Kx9mQ2vTpL7rB4nW8sJfD6yHcE3aZgUo
    config/settings.json, docs/setup.md

[home-path] ホームディレクトリのパス。ユーザー名が埋まっていることが多い
  /home/acme-operator  (履歴のみ)
    systemd/worker.service
```

**2. 消すものを決めて、設定に記録する**

```toml
# publish-guard.toml
[forbidden]
terms = [
  "AcmeCorp",
  "1Kx9mQ2vTpL7rB4nW8sJfD6yHcE3aZgUo",
  "/home/acme-operator",
  "売上高",
]
```

素の文字列だけ書けば大丈夫です。別表記は自動で導かれます。

**3. 好きな方法で消して、確認する**

```sh
python -m publish_guard.cli verify /path/to/repo -c publish-guard.toml
```

```
走査: 42 コミット / 310 blob / 禁止語 4 件

検出: 3 件 / 1 語

  売上高
    %E5%A3%B2%E4%B8%8A%E9%AB%98  ← 別表記
      test/import-verification.test.js  (現在も存在)

「履歴のみ」の検出があります。ファイルを編集しても消えません。
git push --force でも GitHub 側のオブジェクトは残ります。
確実に消すには、リポジトリを作り直してください。
```

## CI に置く

```yaml
- name: publish-guard
  run: python -m publish_guard.cli verify . -c publish-guard.toml
```

**一度見つけることが目的ではありません。** 意識しなくなった後も見つけ続けることが目的です。

## やらないこと

**置換はしません。** 何を消すかは判断であって、機械に推測させると漏らす方向に外れます。消し方はご自身のやり方で構いません。このツールは結果の確認だけを担当します。

**何が機密かは教えられません。** `scan` は形から候補を挙げるだけで、どれが重要かを知っているのはあなただけです。

**履歴の掃除もしません。** 履歴にしか残っていないものを、このツールのコマンドで消すことはできません。確実なのはリポジトリを作り直すことで、`verify` はそれが必要かどうかをお伝えするところまでを担当します。

## オプション

| | |
|---|---|
| `--no-history` | HEAD の tree だけを走査します。速いのですが、**このツールの存在理由そのものを見逃します**。コミット前の下見用であって、公開前の確認には使わないでください |
| `--current-branch` | 全 ref ではなく現在のブランチの履歴だけを走査します。祖先は辿るので、「履歴を見ない」という意味ではない点にご注意ください |
| `--limit N` | `scan` でカテゴリごとに表示する件数（既定 20） |

## 終了コード

| | |
|---|---|
| `0` | 検出なし |
| `1` | 検出あり |
| `2` | git リポジトリでない、または設定エラー |

## テスト

```sh
python -m unittest discover -s tests -t .
```

依存のインストールは不要です。一時ディレクトリに実際の git リポジトリを作り、**後のコミットで消した値が今も見つかること**と、**派生した表記がすべて捕まること**を検査しています。

## このツールを作っている最中の話

この README の最初の版では、実体験に基づく例のほうが良いだろうと考えて、実物の識別子や社内用語をそのまま例として書いていました。それを見つけるためのツールの、README とテストの中にです。誰かが clone する前に気付いて、リポジトリを作り直しました。

書き残しておきたいのはここから先です。`scan` はそのうちのひとつを、すでに候補として表示していました。私はその出力を読んだうえで、「テストのための例だから問題ない」と判断して先に進めています。

ツールは正しく動いていて、それを読んだ人間のほうが判断を誤ったことになります。`verify` が終了コード 1 を返し、CI に置かれるべき理由はここにあります。忘れてしまうからではなく、**警告を見た上で自分を納得させてしまうから**です。
